# Веб-приложение для коллективной работы над замечаниями рецензентов

Веб-приложение, разработанное для автоматизации и поддержки совместной работы авторских коллективов над доработкой научных статей по замечаниям рецензентов. Система позволяет структурировать процесс доработки, декомпозировать замечания рецензентов на задачи, отслеживать их прогресс выполнения, формировать и экспортировать итоговый ответ для последующей отправки в редакцию журнала.

## Описание проекта

### Основные возможности системы

- **Управление проектами и участниками:** Создание проектов, управление участниками проекта, добавление рецензентов и их замечаний.
- **Ролевая модель:** Реализована строгая ролевая модель доступа.
- **Интерактивная Канбан-доска:** Отслеживание статуса задач с поддержкой функции drag-and-drop. Синхронизация действий пользователей и перерисовка интерфейса происходят в режиме реального времени через WebSockets.
- **Интегрированный Markdown-редактор:** Поддержка сложной научной верстки и математических выражений (LaTeX) с мгновенным предпросмотром.
- **Система вложений и чата:** Загрузка дополнительных материалов к задачам, автоматическое определение кодировок и предпросмотр документов прямо в браузере. Обсуждение задач в интегрированном чате.
- **Генерация черновика ответа:** Возможность сгенерировать черновик ответа рецензенту с помощью ИИ-модуля.
- **Экспорт результатов:** Конвертация итогового ответа рецензенту в `PDF/LaTeX/DOCX` формат для отправки в редакцию журнала.
- **Журнал активности:** Прозрачное логирование действий пользователей в системе.

### Ролевая модель

- **Автор** — создает проект, формирует задачи, ведет работу над замечаниями.
- **Соавтор** — выполняет задачи, добавляет комментарии и прогресс выполнения.
- **Редактор** — контролирует качество, отслеживает общий прогресс и осуществляет финальное утверждение подготовленных ответов перед их отправкой.
- **Администратор** — управляет пользователями, проектами и логами системы.

## Развертывание приложения

### Упрощенное развертывание

Развертывание системы автоматизировано с помощью bash-скрипта `setup.sh`. Скрипт проверяет наличие зависимостей, настраивает права доступа, генерирует SSL-сертификаты и запускает сервисы.

1. Склонируйте репозиторий:
   
   ```bash
   git clone https://github.com/DemidAntipin/review_web_platform.git
   cd review_web_platform
   ```
   
2. Создайте файл `.env` в корне проекта (используйте `.env.example` как шаблон) и заполните системные переменные:

    - `DB_USER`. Имя пользователя СУБД PostgreSQL, от имени которого будут открываться асинхронные сессии с базой данных (должен обладать полными правами на чтение и запись для указанной БД).
    - `DB_PASSWORD` Указать настоящий пароль пользователя СУБД.
    - `DB_NAME` Название целевой базы данных в PostgreSQL, в которой разворачивается структура таблиц приложения.
    - `SECRET_KEY` Секретный ключ, использующийся для JWT токенов.
    - `ALGORITHM` Алгоритм хеширования, применяемый для шифрования и подписи JWT-токенов (например, `HS256`).
    - `ACCESS_TOKEN_EXPIRE_MINUTES` Срок действия токена доступа (access token) в минутах, определяющий время активной сессии пользователя до необходимости повторной авторизации.
    - `AI_API_KEY` Секретный API-ключ для интеграции с большой языковой моделью, используемый для авторизации запросов к нейросети. При возникновении ошибок в работе модуля ИИ проверьте корректность этого ключа.
    - `AI_URL` Базовый URL-адрес API-провайдера искусственного интеллекта, куда бэкенд отправляет запросы на генерацию ответов.
    - `AI_MODEL` Идентификатор конкретной используемой версии языковой модели (например, `deepseek-v4-flash`)

3. Запустите скрипт инициализации от имени суперпользователя (этот скрипт автоматизирует все шаги, включая сборку Docker-образов и запуск контейнеров):
    
    ```bash
    chmod +x setup.sh
    sudo ./setup.sh
    ```

4. Приложение будет доступно по протоколу HTTPS на порту конфигурации Nginx.
    
    - Пользовательский интерфейс (Frontend) доступен по корневому адресу `https://localhost` (или по вашему настроенному домену).
    - Серверная часть доступна по маршруту `/api`
    - Автогенерируемая API документация (Swagger UI) доступна по маршруту `/docs`.

### Ручное развертывание (без Docker)

Следуйте [инструкции](#упрощенное-развертывание) упрощенного развертывания вплоть до пункта 3

#### База данных PostgreSQL

1. Установите сервер PostgreSQL:
    
     ```bash
    sudo apt update
    sudo apt install postgresql postgresql-contrib -y
    ```

2. Запуск сервиса:
    
    ```bash
    sudo systemctl start postgresql
    sudo systemctl enable postgresql
    ```

3. Создание базы данных и пользователя
    
    ```bash
    # Переходим в оболочку postgres
    sudo -i -u postgres psql
    ```

    Замените `DB_NAME`, `DB_USER`, `DB_PASSWORD` на значения из файла `.env`.

     ```sql
     -- Создаем базу данных
    CREATE DATABASE `DB_NAME`;

    -- Создаем пользователя с паролем
    CREATE USER `DB_USER` WITH PASSWORD `DB_PASSWORD`;

    -- Даем пользователю права на базу
    GRANT ALL PRIVILEGES ON DATABASE `DB_NAME` TO `DB_USER`;

    -- Передаем базу данных пользователю.
    ALTER DATABASE `DB_NAME` OWNER TO `DB_USER`;

    -- Выход
    \q
    ```

#### Клиент

1. Установка Node.js и npm
    
    ```bash
    sudo apt update
    sudo apt install nodejs npm
    ```

2. Установка зависимостей
    
    ```bash
    cd ../frontend
    npm install
    ```

3. Запуск локального сервера разработки Vite
    
    ```bash
    npm run dev -- --host
    ```

#### Nginx

1. Установка веб-сервера Nginx
    
    ```bash
    sudo apt install nginx -y
    ```

2. Генерация SSL-сертификатов
    
    ```bash
    sudo mkdir -p /etc/nginx/ssl
    sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
    -keyout /etc/nginx/ssl/key.pem \
    -out /etc/nginx/ssl/cert.pem \
    -subj "/C=RU/ST=Irkutsk/L=Irkutsk/O=Development/CN=localhost"
    sudo chmod 644 /etc/nginx/ssl/cert.pem /etc/nginx/ssl/key.pem
    ```

3. Создание конфигурационного файла проекта
    
    ```bash
    sudo nano /etc/nginx/sites-available/review_app.conf
    ```

    Вставьте в файл содержимое [шаблона](./nginx/default.conf), скорректировав пути и порты под вашу систему.

4. Включение конфигурации и отключение дефолтного сайта
    
    ```bash
    sudo ln -s /etc/nginx/sites-available/review_app.conf /etc/nginx/sites-enabled/
    sudo rm /etc/nginx/sites-enabled/default
    ```

5. Тестирование и перезапуск Nginx
    
    Перед перезапуском службы обязательно проверьте конфигурацию на синтаксические ошибки
    
    ```bash
    sudo nginx -t
    ```

    Если терминал вывел `syntax is ok` и `test is successful`, перезапускайте сервер:

    ```bash
    sudo systemctl restart nginx
    ```
